This is a source/contract reference, not a verification report. Read

CURRENT OPERATIONAL SCOPE

Existing monitoring, named-plan switching, current-plan verification, startup,
exact legacy handover, IPC ownership and recovery remain operational. The 2.3
policy additionally supports optional foreground eligibility, battery guard,
local-time gating, per-game plan overrides and process-tuning master control.
Default process semantics remain any matching watched process, not Steam App ID.

Explicit power tools import/export .pow, duplicate a selected plan, and open
Windows advanced settings. Native tray, close-to-tray, start-minimized, global
shortcut registration, theme sync, native frame, process picker and session
exports now have real handlers. The desktop telemetry HUD uses a separate native
window without injecting into games. These are no longer UI-only previews.

Sensor readings are conditional: persistent NVIDIA NVML / supported AMD ADL8
PMLog readers supply independent GPU temperature/utilization/fan percentage/RPM
values, nominally every two seconds while visible/HUD-enabled. A separate bounded
ten-second WMI worker can read CPU/package/board values and GPU fallback from
existing LHM/OHM providers. Explicit Retry can bypass the cadence; no provider or
driver is installed. Missing values remain unavailable; measured zero is valid.
The WMI schema does not expose acquisition timestamps and can be externally
cached. Selected GPU identity/provenance is retained; partial GPU readings are
not combined with another adapter. No energy meter/baseline is implemented.

CPU PDH sampling is nominally one second while foreground Overview is visible,
or the optional HUD requests samples. Fullscreen suspension and missing telemetry
invalidate stale CPU readings. P/E/total paths use fresh timestamped samples in a
30-second window; missing intervals are gaps. Actual measured zero stays zero.
Values measure interval busy time, not instantaneous process-to-core ownership.

Session totals use this GUI window's observed active-plan intervals and monotonic
elapsed time. Unknown plans/disconnected periods are excluded. External changes
while the detector is paused are not independently audited. Timeline records up
to 64 events; new events contain captured source/target, available process/PID,
engine Windows account and power API duration. Missing legacy metadata says so.
Duration is not total detection latency. All events are scrollable/clickable.
Session export JSON schema 2 adds current_state; CSV includes a state row and
status/error/backend/automation/current-plan columns. Dedicated diagnostic JSON
also includes selected-event detail and the last 64 KiB of native.log with explicit
truncation/read-error metadata. The controller calls diagnostic_json on its worker;
no unbounded log read runs on the Slint event loop. Account/process/plan names may
appear in exported data; old failures outside the retained tail are not guaranteed.

PUBLIC INTERFACE COMPATIBILITY

GameRow, CoreRow, HistoryRow, AppWindow, Theme and Shortcuts retain existing names
and fields. Existing callback/property names are preserved. Slint property names

TOPOLOGY PRESENTATION CONTRACT (2.3.3)
cpu-vendor / cpu-model         string; CPUID identity, explicit unknown fallback
topology-summary/detail        string; model/counts, source and limitations
p-core-count / e-core-count    int; classified physical cores, SMT counted once
is-hybrid                     bool; Intel with distinct Windows efficiency classes
has-l3-groups                 bool; verified AMD shared L3 mappings available
l3-groups                     [int]; shared L3 domain ID per displayed core row;
                              -1 when unavailable, not a Windows group or CCD ID
has-ccx                       bool; reserved compatibility input, remains false
ccx-groups                    [int]; reserved compatibility mapping, all -1;
                              no invented CCX IDs are exposed
core-sections                 [CoreSection]; contiguous ranges in cores model
core-rows-8/12/16              int; cached sum of section grid rows per column count

CoreRow adds class:string; P or E only for justified Intel classes, otherwise C.
LP-E and CCX labels are not inferred from efficiency/cache size. Existing label,
fill, activity and detail fields remain intact. CoreSection has title/detail/class,
start/count and rows-8/rows-12/rows-16 cumulative row offsets. All names are additive.
Section IDs are presentation identifiers, distinct from Windows processor groups.

src/cpu_topology.rs calls GetLogicalProcessorInformationEx once during startup.
It reads active physical-core masks, EfficiencyClass and shared L3 relationships;
standard Rust CPUID intrinsics supply identity only. It does not pin threads,
alter scheduling, or rely on CPUID 0x8000001E as a universal AMD CCD/CCX decoder.
AMD asymmetric L3 is reported as observed cache size differences, never proof of
physical CCD count or 3D V-Cache. PDH data joins by (Windows group, logical index).
Missing topology or ambiguous cache mappings retain neutral/unavailable states.
system_integration::cpu_topology() exposes the read-only result; --topology-probe
<absolute.json> exports it without starting a GUI/engine or changing power/startup.
No additional topology crate was needed; nvml-wrapper remains pinned to 0.13.0.

Sensor display requires sensors-available and individual value>=0. CPU 75/90°C
and GPU 75/85°C tint thresholds are display cues, not manufacturer-specific

CAPABILITY FLAGS
All default false in Slint and are assigned by the actual controller:
sensors-available, power-tools-available, tray-available, automation-available,
visual-overlay-available, hotkeys-available. A true hotkey capability permits
registration attempts; it does not mean the selected chord registered. Read
hotkey-status for results. Connect sensors stays enabled when readings are absent.
elevated-plan-retry is an additional bool display input (default false). It shows
Retry with Windows approval only after a privilege-denied plan-file operation.
pro-command("retry-elevated") retries the controller's retained exact operation;
monitoring remains unelevated and no automatic elevation occurs. See the release
report for elevated-path verification status.

Application shortcuts require a modifier and supported key. Ctrl/Alt/Shift/Win
plus A-Z,0-9,F1-F24 except reserved F12, Space, Enter, Home/End/PgUp/PgDn are
validated by the parser. The two shortcuts must differ. Apply reports conflicts.
Ctrl+Alt+P is a manual plan toggle; Ctrl+Enter inside NN6 toggles monitoring.
Manual selection clears on pause/resume or next game lifecycle. Battery guard
still takes precedence. Close-to-tray keeps the engine available; explicit Exit
restores Default and changed scheduling. See recovery limits in README.txt.

ENGINE POLICY FIELDS
 auto-switch-battery => Config.battery_guard Option<bool>
 auto-apply-affinity => Config.auto_affinity Option<bool>
 foreground-only    => Config.foreground_only bool (default false)
 auto-time-rule     => Config.time_rule bool
 automation-start/end => Config.time_start/time_end HH:MM local time
 per-game plan-kind 2 => Game.power_plan string (empty uses global Gaming)

The affinity master is labeled Auto-apply process tuning because it governs
saved affinity AND priority. It has no unused global policy text field. The
retained automation-affinity property is compatibility-only and not displayed.
Time inputs use private drafts; Apply copies them into the public fields and
validates through Rust. Fresh snapshots cannot overwrite half-typed inputs.
Time rules gate game eligibility rather than creating a running-game state.
Battery guard selects Default on DC or unknown source. First matching saved
profile decides the target when several eligible games are running.
Failed policy application retains a retry while battery/time policy is enabled;
the next bounded five-second tick retries even if source/time is unchanged, then
success clears the flag. With both rules disabled, the existing event-driven
failure recovery waits for another event or action. Settings and imported profiles
share configure preflight, dirty-restoration rejection and rollback paths.

EXPORTED TELEMETRYHUD WINDOW
Separate no-frame 220 × 72 Slint Window; public in string plan-name/cpu-text/sensor-text
and in float alpha 0..1. Rust supplies measured values and configures native
Windows topmost/click-through position and opacity. The HUD is distinct from the
Windows best-performance power overlay. No game-memory access or game hook is
used to draw it. It does not promise display over every exclusive fullscreen game.
Disabling aborts pending setup and drops the component/native adapter. Enabling
creates it lazily and awaits Winit HWND readiness before native positioning.
The main window retains its renderer and may retain a cached GPU surface while
hidden, but visible model/chart work and decorative animation are suspended.
Stable VecModels and changed-row updates introduced in 2.3.2 remain in use.

GUI SINGLETON AND TRAY NOTICE
The GUI-only per-user/session Global mutex is acquired before Slint initializes;
the engine/guardian ownership remains separate. Duplicate requests queue SHOW
onto the owner event loop. notify_already_running() queues an optional native
tray balloon using the existing registered icon, at most once per five seconds.
Quiet time and notification suppression are respected; the notice is silent and
real-time only. Ok means queued, not displayed. No icon is created for a notice.

DETECTION WORDING
The badge reports actual WMI/Win32 compatibility or trace operation plus the
optional foreground hook. This is not an app-owned ETW session. Detection does
not inject into games or scan their memory. Process tuning is a separate optional
Windows scheduling mutation. There is no EAC/BattlEye/Vanguard certification or
ban guarantee, and event-driven callbacks do not establish zero CPU overhead.
